# 飞牛音乐 · FnMusic

FnMusic 是面向 Windows 10 22H2 和 Windows 11 x64 的第三方飞牛音乐桌面客户端。主窗口使用 Rust 和 egui，Windows MediaPlayer 负责音频解码与输出。WebView2 用于打开飞牛官方 NAS 账号授权页。

## 使用

1. 在飞牛 NAS 上启用飞牛音乐，并确保当前 Windows 电脑能够访问服务。
2. 启动 `fnmusic.exe`，选择「IP / 域名」后填写 NAS 地址，例如 `192.168.1.10:5666` 或 `https://nas.example.com`。可以填写带反向代理前缀或 `/music` 的地址。也可以选择「FN Connect」，填写 FN ID（如 `my-nas`）或链接（如 `https://fnos.net/my-nas`）；地址模式下粘贴完整 FN Connect 链接也会自动识别。
3. 选择「使用 NAS 账号登录」，在弹出的飞牛官方页面完成授权。HTTPS NAS 支持自签名、过期或域名不匹配的证书，无需导入 Windows 信任库：接口、封面、音频流和授权窗口会对填写的 NAS 地址忽略证书错误。连接仍使用 HTTPS 加密，但不验证该 NAS 的证书身份，请填写自己信任的 NAS 地址。其他地址和自动更新下载继续严格校验证书。
4. 从首页或资料库打开专辑、艺人和歌单，点击歌曲开始播放。使用 `Ctrl+F` 定位搜索框，使用空格键控制播放。点击底部的封面、歌名或艺人可打开歌词详情，按 `Esc` 返回资料库。点击带时间戳的歌词可跳到对应位置。

侧边栏在窗口宽度低于 980 个逻辑点时自动折叠。较宽的窗口可用 `Ctrl+B` 切换侧栏。在宽度低于 1240 个逻辑点时，歌词和队列面板以浮层打开。导航栏按钮、`Alt+←` / `Alt+→` 和鼠标侧键均可前进或后退，并恢复已加载页面的滚动位置。

歌曲列表支持点击列头对已加载歌曲排序。单击选择，`Ctrl` 多选，`Shift` 连选，`↑` / `↓` 移动选中行，双击或按 `Enter` 播放。右键或点行尾的更多图标可批量加入队列或收藏。也可以把选中的歌曲拖到侧栏的「喜欢的歌曲」，或拖到展开侧栏中的具体歌单。

播放栏中央提供播放／暂停主按钮，两侧排列随机、切歌和循环。右侧提供音质菜单、播放列表和音量控制；进度条悬停可预览时间。源文件音质信息来自 NAS 元数据。音质档位请求是否生效取决于 NAS 接口支持，目前尚未验证服务器转码能力。账户菜单中的「外观与主题色」可选择浅色、深色或跟随系统，并切换经典红、墨绿或海蓝。

首页卡片和侧边栏提供「每日推荐」：从 NAS 曲库生成最多 30 首，参考收藏歌曲与艺人偏好，优先分散艺人和专辑，并降低最近 7 天已推荐歌曲的选中概率。没有收藏时提供曲库发现，小曲库会展示实际可用数量。同一天的列表按账号保存在本地，重启后保持一致；按 Windows 本地日期更新，跨天不会打断当前播放。可一键播放、整批加入播放列表，或使用歌曲行的收藏与更多菜单。推荐只使用 NAS 曲库和本地缓存，不向第三方上传曲库或偏好。大曲库采用分散分页采样，每次最多读取 4,000 首候选及 1,000 首收藏，只补全最终推荐歌曲的封面信息。

关闭窗口默认留在系统托盘并继续播放。单击托盘图标显示窗口，右键菜单可播放／暂停、切歌或退出。再次启动同一数据目录下的应用会唤醒已有窗口。侧栏底部的头像账户菜单可设置「关闭窗口时 → 直接退出应用」，也可分别「退出登录」或「退出飞牛音乐」。托盘菜单中的关闭选项与账户菜单同步，重启后保留。

Windows 媒体面板和键盘媒体键可控制播放／暂停、上一首、下一首；媒体面板显示歌名、艺人、专辑和播放进度，支持跳转。窗口标题和托盘提示跟随当前歌曲。系统托盘初始化失败时，关闭窗口会正常退出，避免应用隐藏后无法找回。

退出并重新启动应用后，队列、位置和音量会按服务器和账号恢复，等待手动开始播放。默认数据目录为 `%LOCALAPPDATA%\FnMusic`，其中会话文件使用当前 Windows 用户的 DPAPI 加密。退出登录会清除会话凭证和该授权窗口的浏览数据，并清除系统媒体信息。

FN Connect 连接使用官方公开网关解析 HTTPS 中继地址，NAS 必须已启用 FN Connect 且在线，并能通过中继访问飞牛音乐。仅 FN ID 发送给网关；账号授权和音乐请求都发往 NAS 的中继入口。当前使用 HTTPS 中继，不包含官方客户端的 P2P 通道或自动切换直连；速率和可用性受 FN Connect 服务限制。重启时重新解析中继地址，播放记录按 FN ID 与账号保存。

## 从源码构建

账户菜单中的「动画效果」可选择开启（默认）、跟随系统或关闭。当前提供按钮悬停与按压反馈、播放状态淡化切换、收藏光环、切歌和页面淡入、歌词高亮与滚动过渡，以及歌词开关对应的封面居中移动。菜单和设置窗口使用 egui 的淡入效果；关闭动画后立即切换。运行中选择跟随系统时，会读取 Windows 的客户端区域动画设置。

播放详情的背景会从封面取色，切歌时平滑过渡，浅色模式使用淡色背景。浅色／深色切换也提供渐变过渡。正在播放的歌曲在歌曲列表和播放列表中显示动态音符柱，暂停或关闭动画后静止；页面和封面加载时显示骨架占位。

手动滚动歌词后暂停自动跟随，可点击「回到当前歌词」恢复，点击某行仍可跳转；切歌后恢复跟随。右键点击底部封面或歌曲信息、详情页更多菜单、播放列表更多菜单可找到「定位当前歌曲」（打开播放列表并滚动到当前项）和「播完列表后清空」。启用播完清空会关闭循环，重新启用循环则取消播完清空，该选项随账号队列保存。

账户菜单和上述播放菜单提供「睡眠定时」：15／30／60／90 分钟后暂停，或本首结束后暂停。按分钟定时会保留播放进度，本首结束模式停在当前歌曲开头；定时仅本次运行有效，退出登录后取消。定时到期优先于自动切歌，播放列表显示剩余时间，可随时在菜单中关闭。

需要 Windows x64、Rust stable MSVC 工具链、Visual Studio 的「使用 C++ 的桌面开发」构建工具与 Windows SDK。运行应用需要 Microsoft Edge WebView2 Runtime 和 Windows 媒体组件。Windows N 版可从系统设置添加 Media Feature Pack。

```powershell
rustup default stable-x86_64-pc-windows-msvc
cargo build --release --locked
cargo test --locked
```

Release 文件位于 `target\release\fnmusic.exe`。调试时可使用 `cargo run --locked`。

## GitHub 自动打包

提交到 `main`、提交 Pull Request 或手动运行 Actions 中的 `Windows build and package`，将执行格式检查、测试和 Windows x64 Release 构建。成功后可在运行记录的 Artifacts 下载便携 ZIP 和 SHA-256 校验文件。包内含程序、说明和许可证；运行仍需要 WebView2 Runtime。

正式发布仅由版本标签触发，不再随着 main 提交覆盖滚动预览版。标签必须与 Cargo.toml 的版本一致，例如当前版本为 `0.2.2`，则使用 `v0.2.2`。版本不一致会停止构建；已公开的同名版本不会被覆盖，应递增版本号后重新发布。

发布步骤：修改 Cargo.toml 的版本并同步 Cargo.lock，提交代码，然后执行 `git tag v0.2.2` 和 `git push origin main v0.2.2`。后续版本相应替换版本号。流水线先构建和检查，再把所有附件上传到草稿 Release，最后公开为最新正式版本。发布任务单独获得仓库内容写权限，不需要额外配置访问令牌。

Release 提供带版本号的便携 ZIP（如 `FnMusic-v0.2.2-windows-x64.zip`）、独立的 `fnmusic.exe`、自动更新元数据 `update.json` 和 `SHA256SUMS.txt`。旧的 preview 仅作历史下载保留，不再自动刷新。版本变更见 [更新记录](CHANGELOG.md)。

## 应用内更新

从 v0.2.0 起支持应用内更新。启动数秒后会检查 GitHub 最新正式版本，发现新版时显示更新说明，由用户选择「下载并重启更新」或稍后处理；不会自行安装。账户菜单 →「检查更新…」和登录页的版本链接可手动检查，更新窗口可关闭「启动时检查更新」。旧版客户端需要先手动下载一次 v0.2.0，之后才能使用这个入口。

更新下载采用独立的 HTTPS 连接，不携带 NAS Cookie 或账号凭证。只从本仓库正式 Release 获取 Windows x64 程序，检查版本、文件大小、SHA-256 和程序格式；下载可取消。新版会先写入安装目录，再退出旧进程、替换文件并重启，账号数据和队列仍保存在原数据目录。新版未能启动时会尝试恢复旧程序。更新目录不可写时会保留当前程序并提示前往发布页面手动下载。

便携版建议解压到当前用户可写的文件夹。更新暂存文件放在数据目录的 `updates` 下，超过七天的旧暂存目录会在启动时清理。更新功能需要能够访问 GitHub；网络失败不会影响 NAS 播放，可稍后重试或手动下载。

## 使用模拟服务器联调

在 [上游项目](https://github.com/Raduap/FN-Music-Apple) 目录运行 `npm run mock`，或者直接用 Node.js 运行上游的 `dev/mock-server.js`。在 FnMusic 中填写 `127.0.0.1:5666`，在模拟授权页输入任意测试值。`FNMUSIC_DATA_DIR` 可为联调指定独立的数据目录。模拟服务器提供 WAV 音频、SVG 封面和带时间戳的歌词。

```powershell
cargo test --locked --test protocol upstream_mock_contract -- --ignored
```

如模拟服务使用其他端口，设置 `FNMUSIC_MOCK_URL`，并使用本机地址。桌面验收时依次检查 NAS 授权、浏览、中文搜索、收藏、切歌、进度跳转、歌词跳转、关闭后恢复和退出登录。

也可以用 `node .\tests\mock-upstream.cjs <上游 dev/mock-server.js 的路径>` 启动自动授权的回环测试服务。在另一个 PowerShell 中运行客户端流程测试。

```powershell
$env:FNMUSIC_DATA_DIR = Join-Path $env:TEMP ('FnMusic-test-' + [guid]::NewGuid())
cargo test --locked --bin fnmusic mock_app_playback_restore_and_logout -- --ignored
```

- Windows 11 x64 已构建并启动 Release。WebView2 回归测试覆盖授权窗口与主窗口共存、回调捕获、浏览数据清除。
- Windows 原生系统集成测试已验证托盘创建、系统媒体会话的暂停／跳转／下一首回调，以及真实 eframe 窗口关闭后隐藏、第二次启动唤醒、切换设置后直接退出。模拟 NAS 回归另覆盖系统播放命令、动态标题和关闭设置重启恢复。

- 真实 NAS 的飞牛音乐版本为 1.0.10。已在官方授权窗口完成登录，并使用该会话通过客户端的音频转发播放一首 FLAC，跳转到第 4 秒。Windows 10 22H2 的实机验证待进行。
